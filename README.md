# くずし字列分割アノテーションツール

日本古典籍くずし字データセットの列分割アノテーションを行うWebアプリケーションです。各文字のbboxを列単位でグループ化し、アノテーションをCSVに保存します。

## 機能

- ページ画像上で文字のbboxを可視化
- キーボード/タッチ操作による効率的な列分割
- X座標に基づく列の自動推定（Autoモード）
- 書籍ごとの統計モデルによる列/セグメント推論
- 全書籍共通モデル + 書籍別モデルの二段構え推論
- human in the loop での予測修正と継続学習
- 書籍ごとのモデル状態、学習時 metrics、HITL feedback の可視化
- 列単位でのbbox表示と色分け
- 列/セグメント表示の切り替え
- 列アノテーションからセグメント（Segment ID）を自動推定して出力
- Undo/Redo対応

## 必要要件

- Python 3.12以上
- uv（パッケージマネージャー）

## インストール

```bash
# リポジトリをクローン
git clone --recurse-submodules <repository-url>
cd kuzushiji-column

# 既存クローンの場合は converter サブモジュールを取得
git submodule update --init --recursive

# 依存パッケージをインストール
uv sync
```

## データの準備

`raw/` ディレクトリに以下の構造でデータを配置してください：

```
raw/
└── {book_id}/
    ├── {book_id}_coordinate.csv   # 文字座標CSV
    └── images/
        ├── {page_id}.jpg          # ページ画像
        └── ...
```

### 座標CSVの形式

| 列名 | 説明 |
|------|------|
| Image | ページID（画像ファイル名から拡張子を除いたもの） |
| Unicode | 文字のUnicodeコードポイント |
| X | bboxの左上X座標 |
| Y | bboxの左上Y座標 |
| Width | bboxの幅 |
| Height | bboxの高さ |
| Char ID | 文字ID（例: C0001, C0002, ...） |
| Block ID | ブロックID（オプション） |

## 起動方法

```bash
uv run python main.py
```

この起動方法ではホットリロードが有効です。`main.py` を変更すると開発サーバーが自動再起動します。

ブラウザで http://localhost:8100 を開きます。

別コマンドで起動する場合も、同じくホットリロード付きで `8100` 番ポートを使ってください。

```bash
uv run uvicorn main:app --reload --host 0.0.0.0 --port 8100
```

## 使い方

### 基本操作

1. 書籍とページを選択（起動時は自動で最初のページを表示）
2. ↓キーで列の最後の文字まで移動
3. 次の列の先頭文字でEnterキー → 直前までが列として確定
4. 最後の列は、最後の文字でEnterキー → 残り全部が確定
5. Sキーで保存 → アノテーションCSVを更新

### 表示モード

ツールバーのトグルで「列」表示と「セグメント」表示を切り替えられます。

### KCR取り込み確認

ツールバーの「KCR取込」から `/kcr-import` を開くと、`kcr_import/candidates.json` に登録されたページだけを巡回できます。画像上の枠と右側の拡大画像を照合し、候補ごとに判定してください。

- 新規・近接候補は「追加する」または「却下」を選べます。重複候補の初期値は「自分の箱を残す」で、座標だけの差し替えや両方の箱を残すこともできます。
- 文字の追加には `U+3042` または `あ` のような Unicode 入力が必要です。未判定のものは残したまま、判定した分だけをページ単位で保存できます。
- 保存済み候補は `kcr_import/decisions.jsonl` に記録され、再起動後も候補一覧から除外されます。却下だけの場合、CSV は変更されません。
- 書き換え前の CSV は `kcr_import/backups/` に保存されます。座標は `raw/{book}/{book}_coordinate.csv` を正本とし、`raw_csv/` がある場合は同じ内容を同期します。`output/` と `output_seg/` は対象ページに既存行がある場合にだけ更新します。
- 追加時はそのページの Char ID を振り直しますが、既存文字の列・割注・セグメント属性は引き継ぎます。追加した文字の属性は空欄なので、必要に応じて通常モードで割り当て直してください。

### キーボードショートカット

| キー | 操作 |
|------|------|
| ↑ / ↓ | 文字選択を移動 |
| ← / → | 前後のページへ移動 |
| Shift + → | 保存せず次のページへスキップ |
| Enter | 列を確定（選択した文字から新しい列開始） |
| N | 選択文字を未分割に戻す |
| Shift + N | 全解除（全て未分割に戻す） |
| Z | 元に戻す (Undo) |
| Y | やり直し (Redo) |
| S | 保存 |
| H | ヘルプを表示 |
| E | 選択列のボックスを右側に広げる（「右側に追加 (px)」の値だけ。「上下に追加 (px)」も同時に上下へ広げる） |
| Shift + E | 選択列のボックスを右側から狭める（最小幅 8px。上下も同時に狭める） |
| G | 全列のボックスを広げる（「右側に追加 (px)」と「上下に追加 (px)」の値だけ） |
| W | 割注の範囲指定（1回目で開始、終了文字を選んで2回目で確定。開始文字で再実行すると取り消し） |
| Shift + W | 選択文字を割注の右/左の境目にする（選択文字から後ろを左側にする） |

### 割注

割注（行内で2行に割って書かれた注）を、列の中の文字範囲として印付けできます。列表示（列編集モード）でのみ操作できます。

- 範囲の指定: 開始文字を選んで `W`（または右パネル「割注」の「範囲を開始/確定」）、同じ列の終了文字を選んで再度 `W` で確定します。開始文字は列に割り当て済みで割注に含まれていない文字、範囲は2文字以上で既存の割注と重ならないことが条件です。
- 右/左の自動振り分け: 範囲内の文字を列内の順に並べ、前半の X 中心の平均と後半の X 中心の平均の差（前半 − 後半）が最大になる位置で分割します。前半が右、後半が左です。
- 手直し: 境目にしたい文字（左側の先頭）を選んで `Shift + W`（または「選択文字を境目にする」）を押します。範囲の先頭文字は境目にできません。
- 解除: 「選択文字の割注を解除」で、選択文字が属する割注全体を解除します。
- 列を分割したり、文字を未分割に戻したり、全解除や自動推定をしたりして、割注が列をまたぐ・列内で連続しなくなる場合は、その割注が自動的に解除されます。
- 割注の操作は Undo / Redo の対象で、保存すると CSV に反映されます。画面では右/左それぞれの文字範囲が破線の矩形で表示されます。

### 列ボックス

縦書きでは、ふりがなや返り点が列の右側（+X）に付きます。列ボックスは、列の枠を文字の範囲より広げてこれらを含めるための機能です。

- 既定（自動）: 列ボックスは列内の文字 bbox の和集合です。
- キャンバス上のドラッグ: 全列の右辺・上辺・下辺、および選択列の左辺をドラッグしてサイズを変更できます（最小 8px、画像範囲内に収まります）。
- 右パネル「列ボックス」:
  - 「右側に追加 (px)」（既定 40、ブラウザに保存）と「上下に追加 (px)」（既定 0、ブラウザに保存。上へ・下へ各px）を指定し、「選択列を広げる」または「全列を広げる」で一括して右側と上下を同時に広げます（画像範囲・最小 8px の内側で止まります）。
  - 「選択列を自動に戻す」で、選択中の列だけ調整を解除します（すでに自動の列では押せません）。
  - 「全列を自動に戻す」で、すべての調整を解除します。
  - 列を確定（`Enter` / 列確定ボタン）すると、新しくできた列に現在の px 設定（右側・上下）が自動で適用されます。既存の列を途中で分割したときの2列にも適用されます。右側・上下の px がどちらも 0 以下のときは広げません（専用のチェックボックスはありません）。
  - ボックスが1つも調整されていないページでは、読み込み時に現在の px 設定で自動的に全列を広げます。そのまま何も編集せずに次ページへ進むと、自動で保存されます。
  - X / Y / 幅 / 高さを数値入力して「適用」できます（自動の列は有効な値を表示します）。
- キーボード: `E` で選択列の右側（と上下）を広げ、`Shift + E` で狭めます。`G` で全列を広げます。
- 列ボックスの操作は Undo / Redo の対象で、保存すると CSV に反映されます。

### ページの完了条件

ページ一覧の ✅ と、書籍ごと・全体の進捗率（`完了ページ数/総ページ数(%)`）は、次の3つをすべて満たしたページだけを「完了」として数えます。

1. 列アノテーションが保存されている
2. ページ内の全文字に列が付いている（未割当の文字が残っていない）
3. すべての列に明示的な列ボックス（`Column X` / `Column Y` / `Column Width` / `Column Height`）が保存されている

1つでも欠けるページは未完了です（✅ は付かず、進捗にも数えません）。一部の列だけボックスがある場合、未割当文字が残ったまま保存した場合、ボックスなしで保存した古いページも未完了です。保存済みのCSVが、元の座標CSVの文字数より少ない行数しか持たない場合（保存後に元データが変わった場合など）も未完了とします。

- `GET /api/books/{book_id}/pages`: `annotated_pages`（保存済み）に加えて、完了ページの一覧 `completed_pages`（`annotated_pages` の部分集合）を返します。`last_annotated` は従来どおり保存済みページを基準にします。
- `GET /api/books`: `annotated_count`（保存済みページ数）に加えて、`completed_count`（完了ページ数）を返します。`progress` は `completed_count` を基準にします。
- 保存直後は、保存した内容で完了条件を判定して ✅ を更新します。保存済みになったページは従来どおり `annotated_pages` に入ります。

### タッチ操作（スマホ/タブレット）

- ツールバーのボタンで `列確定` / `未分割へ` を実行できます（キーボードなしで操作可能）
- 画像領域の右端にある `↑/↓` ボタンで選択文字を移動できます（押しっぱなしで連続移動）
- セグメント表示中は `列確定` / `未分割へ` が無効化されます（閲覧モード）
- `列確定` は未分割文字がない場合、`未分割へ` は選択文字が未割当の場合に無効化されます

### 表示の見方

- **青枠**: 未割り当ての文字
- **ピンク塗り**: 選択中の文字
- **色付き背景**: 確定済みの列（列ごとに色分け）
- **赤点線**: Char ID順の重心を結ぶ線

### Autoモード

ツールバーの「Auto」トグルをONにすると、既存のアノテーションがないページを開いた時に、まず学習済みモデルによる推論を試みます。モデルが未学習またはサンプル不足の場合だけ、従来のX座標ベース自動推定にフォールバックします。推定結果を修正してから保存できます。

### Human in the Loop

- 列保存後とセグメント保存後に、現在の書籍のモデルをバックグラウンド再学習します
- 同時に、全書籍共通モデルも再学習します
- 新規ページではモデル推論を初期アノテーションとして読み込みます
- 推論の優先順位は `書籍別モデル -> 全書籍共通モデル -> 従来Auto` です
- 推論結果が誤っていれば既存UIで修正し、その保存結果が次の学習データになります
- 予測も保存も、基準は常に単文字 bbox に紐づく `Column ID` / `Segment ID` です
- 左側パネルで、列/セグメントモデルの利用可否、学習サンプル数、学習時 metrics、直近の HITL feedback を確認できます
- 保存時には、初期予測のうち何件が採用され何件が修正されたかを feedback として `output_models/{book_id}/feedback_history.jsonl` に蓄積します

### Hugging Face Dataset 更新

ヘッダーの `HF 更新` ボタンから、保存済みの `raw/`, `output/`, `output_seg/` を使って Hugging Face Dataset を作り直し、Hub へアップロードできます。

この機能はサブモジュール `kuzushiji-hf-converter/` の `convert_dataset.py` を、親プロジェクトから以下の形で実行します。

```bash
uv run --project kuzushiji-hf-converter \
  python kuzushiji-hf-converter/convert_dataset.py \
  --export-format hf \
  --dataset-type both \
  --bbox-format coco \
  --dataset-name-prefix kuzushiji-dataset \
  --raw-dir raw \
  --output-dir hf_output \
  --column-annotations-dir output \
  --segment-annotations-dir output_seg \
  --push-to-hub \
  --max-shard-size 500MB
```

前提:

- `kuzushiji-hf-converter/` サブモジュールが取得済みであること
- `hf auth login` 済み、または `HF_TOKEN` がサーバープロセスの環境変数に設定されていること
- `HF_HUB_USERNAME` または `HF_USERNAME` を設定すると、アップロード先 owner を明示できます

既定ではページ単位 dataset と文字単位 dataset の両方を更新します。作成中のローカル出力は `hf_output/` に保存されます。更新のたびに各 Dataset リポジトリの更新前 `main` を `previous` branch として1コミットに圧縮して保持し、更新後の `main` も1コミットに圧縮します。このため、初回以降は最新世代（`main`）と1世代前（`previous`）だけを保持します。履歴圧縮は不可逆です。手動作成した branch、tag、Pull Request が古いコミットを参照している場合は、それらも古いデータを保持するため個別に整理してください。更新状態は `HF` 詳細ボタン、または以下のAPIで確認できます。

```bash
curl http://localhost:8100/api/huggingface/dataset/update/status
```

converter を直接使う場合の詳細は `kuzushiji-hf-converter/README.md` を参照してください。

### 自動未分割化

未分割の文字に挟まれた文字（連続区間）は、自動的に未分割へ戻されます。ページ読み込み時と列確定後に適用されます。

## 出力ファイル

保存時に以下のファイルが生成されます：

```
output/
└── {book_id}/
    └── column_annotation.csv      # 列アノテーションCSV

output_seg/
└── {book_id}/
    └── column_annotation.csv      # Segment ID を追加した派生CSV

output_models/
├── {book_id}/
│   ├── column_boundary_model.json
│   ├── segment_boundary_model.json
│   ├── training_samples.json
│   ├── training_history.jsonl
│   └── feedback_history.jsonl
└── global/
    ├── column_boundary_model.json
    ├── segment_boundary_model.json
    ├── training_history.jsonl
    └── feedback_history.jsonl
```

保存時に列画像は生成しません。`output/{book_id}/columns/` にある生成済みの列画像はそのまま残ります。

### 出力CSVの形式

- `output/{book_id}/column_annotation.csv`
  - 入力CSVに `Column ID` 列が追加されます（例: COL0001, COL0002, ...）
  - 列ボックスとして `Column X` / `Column Y` / `Column Width` / `Column Height` 列が追加されます（元画像のピクセル、整数）。同じ列の全文字行に同じ値が入り、調整していない列は空欄です（空欄の列は文字 bbox の和集合として扱われます）
  - これらの列がない古いCSVも読み込めます。新しいページを追記するときは、ヘッダーを揃えてファイル全体を書き直します
  - 割注として `Wari ID`（例: WARI0001, WARI0002, ...）と `Wari Part`（`right` / `left`）列が追加されます。割注に含まれない文字は空欄です。`Wari ID` は保存時にページごと・ページ内の文字順に WARI0001 から振り直されます
  - 保存時に、同じ文字が複数の割注に入っている、2文字未満、右のみ/左のみ、複数の列にまたがる、左の後ろに右が続く、といった割注はエラー（HTTP 400）になり、CSV は更新されません
- `output_seg/{book_id}/column_annotation.csv`
  - 上記に加えて `Segment ID` 列が追加されます（例: SEG0001, SEG0002, ...）。列ボックスの列も引き継がれます

セグメント推定アルゴリズムの詳細は `docs/segmentation.md` を参照してください。

## モデル状態 API

- `GET /api/books/{book_id}/models/status`
  - 書籍別モデルと全書籍共通モデル、さらに実際に使われる有効ソースを返します
- `POST /api/books/{book_id}/models/train`
  - 現在の `output/` と `output_seg/` を教師データとして即時再学習します

### 履歴ファイル

- `output_models/{book_id}/training_history.jsonl`
  - 再学習のたびに、列/セグメントモデルのサンプル数と学習時 metrics を1行ずつ追記
- `output_models/{book_id}/training_samples.json`
  - その書籍の境界学習サンプルをキャッシュ。保存時の global 再学習は、全書籍 CSV の再走査ではなくこのキャッシュを集約して高速化します
- `output_models/{book_id}/feedback_history.jsonl`
  - 保存時に、初期予測に対する人手修正量（採用件数/修正件数）を1行ずつ追記
